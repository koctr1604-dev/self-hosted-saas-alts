# 条目字段定义

每个替代方案条目应包含以下字段。分类 Markdown 表格中的列名与此一一对应。

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| SaaS 对照 | 是 | 主要替代的商业 SaaS 名称，可多个，用顿号分隔，例如「Notion、Confluence」 |
| 项目名 | 是 | 官方项目名称（保留英文） |
| 链接 | 是 | 官网优先；若无官网则给 GitHub/GitLab。格式：`[项目名](url)`，可另附仓库链接 |
| 一句话说明 | 是 | 用一句中文说明它是什么、适合谁；避免营销套话 |
| 功能缺口 | 是 | 相对对应 SaaS，自托管版或缺的能力、付费墙、协议限制等。没有明显缺口写「较少」并注明前提 |
| 部署难度 | 是 | 仅三选一：`简单` / `中等` / `较难`（见下方标准） |
| 维护状态 | 是 | 仅三选一：`活跃` / `一般` / `停更或风险`（见下方标准） |
| 备注 | 否 | 许可证、资源占用、自托管限制、与其它条目关系等 |

## 部署难度标准

- **简单**：官方 Docker Compose / 单二进制，常见 VPS 上按文档可在约 30 分钟内跑通；依赖少（例如 Postgres + 应用）。
- **中等**：需要多个服务（DB、缓存、对象存储、邮件等），或需域名与 TLS、OIDC 等额外配置。
- **较难**：多组件可观测性栈、Java/企业级 IdP、Kubernetes 生产化、或官方明确要求较强运维经验。

## 维护状态标准

- **活跃**：近数月仍有稳定发布或主分支提交；社区/文档可用。
- **一般**：仍在维护，但节奏慢、发行版间隔长，或核心能力依赖商业版。
- **停更或风险**：仓库归档、长期无提交、官方转向闭源且自托管路径不稳定、或文档明确不推荐新部署。

## 撰写约定

1. 不编造项目；不确定的链接先核验，404 则删除该条。
2. 产品名、项目名保留英文；说明与缺口用中文。
3. 同一分类内按「更常被提到 / 更适合作为起点」大致排序，不作严格排名。
4. 许可证以项目仓库或官网为准，写在「备注」。
5. 更新条目时同步改 README / SUMMARY 的「最后更新」日期。
